## ⚡️ Ultracode — Dynamic Workflows 自動編排

### 🎯 什麼是 Ultracode？

Ultracode 是 Claude Code 的一個 **effort 設置**，結合：
- **xhigh 推理級別** — 深度思考
- **自動工作流編排** — 並行多代理執行

### 🚀 兩種使用方式

#### 方式 1️⃣：單個任務使用工作流（不改變會話）

在提示詞中包含 **`ultracode`** 關鍵字：

```markdown
ultracode: 根據我的定義書+預算書設計完整的投資監控 Workflow

定義書：
[貼上定義書]

預算書：
[貼上預算書]
```

#### 方式 2️⃣：整個會話啟用 Ultracode

```
/effort ultracode
```

之後所有實質性任務都會自動使用工作流編排。

---

### 💡 工作流執行流程

```
1️⃣ 你輸入 ultracode 指令
   ↓
2️⃣ Claude 規劃工作流階段（多個 Agent）
   ↓
3️⃣ 系統展示計畫 → 需要你批准
   ↓
4️⃣ 你批准後
   ↓
5️⃣ 多個 Agent 並行執行
   • 最多 16 個並發 Agent
   • 每運行最多 1,000 個 Agent
   ↓
6️⃣ 實時監控進度（/workflows 查看）
   ↓
7️⃣ 完成後返回結果
```

---

### ⚠️ 重要：成本考慮

**工作流 vs 逐輪對話的關鍵區別**：

| 方面 | 逐輪對話 | 工作流 |
|------|---------|--------|
| **代理數量** | 1 個（Claude） | **多個（16-1000）** |
| **執行模式** | 順序 | **並行** |
| **Token 消耗** | 基線 | **明顯更高** |
| **適用場景** | 小規模任務 | **大規模/複雜任務** |

> ⚠️ **一個工作流運行會消耗遠多於逐輪對話的 tokens。**

---

### ✅ 什麼時候用 Ultracode？

#### ✅ 適合用工作流的場景
- 📊 大規模任務（監控 50+ 檔股票）
- 🔄 需要多角度分析（籌碼 + 基本面 + 技術面）
- 🔍 複雜邏輯驗證（多個獨立 Agent 交叉檢查）
- 🎯 需要並行處理（時間敏感）

#### ❌ 不適合用工作流的場景
- 💬 簡單對話或調試
- 📝 單一分析任務
- ⏱️ 成本敏感的小任務

在 Claude Code 時代，最聰明的做法是：
- ✅ 花 2 分鐘讓 AI 設計計畫（零成本）

- ✅ 檢查計畫無誤後再執行（確保高效率）

#### 🔑 實戰技巧：節省 Token 的 3 個訣竅

| 訣竅 | 做法 | 省下多少 |

### 💡 新手常犯的 3 個錯誤（避免浪費 Token）

❌ **錯誤 1**：直接要求「執行」（無計畫）
```
用戶說：根據我的定義書，執行 Workflow
後果：可能執行錯誤，需要重新執行，浪費 0.12 Token
```

✅ **正確做法**：
```
用戶說：先展示執行計畫，確認無誤後再執行
結果：計畫確認後執行，高效且無浪費
```

---

❌ **錯誤 2**：修改中途放棄（已消耗 Token）
```
用戶提交 → Claude 開始執行 → 用戶說「等等改一下」
後果：已消耗 Token，無法收回
```

✅ **正確做法**：
```
用戶提交 → Claude 展示計畫 → 用戶確認 → 執行
結果：修改在計畫階段完成，零成本
```

---

❌ **錯誤 3**：不看計畫確認清單
```
用戶盲目同意 → 執行過程發現問題 → 重新執行
後果：浪費 Token + 浪費時間
```

✅ **正確做法**：
```
看清單 → 檢查 5 項要點 → 確認無誤 → 執行
結果：一次成功，高效完成
```

## 🔗 核心理念：Dynamic Workflows

### 舊方式（傳統開發）
```
需求分析（2h）
  ↓
架構設計（3h）    ← 你的時間被浪費在這裡
  ↓
代碼編寫（8h）    ← 這應該由 AI 做
  ↓
調試（4h）        ← 這也應該由 AI 做
  ↓
測試（3h）        ← 低價值工作
  ↓
執行（1h）

總耗時：21 小時
你的貢獻：定義需求（20% 價值）
AI 的貢獻：執行（80% 價值）

❌ 問題：你花 80% 時間做 AI 應該做的事
```

### 新方式（Dynamic Workflows）
```
定義問題（30 分鐘）   ← 你的時間，高價值工作
  ↓
制定預算（15 分鐘）   ← 你的時間，風險管理
  ↓
設定決策規則（15 分鐘） ← 你的時間，商業邏輯

↓ [告訴 Claude Code]

Claude Code 自動做：
  • 架構設計（自動）
  • 代碼生成（自動）
  • 執行監控（自動）

總耗時：1 小時
你的貢獻：定義問題（100% 價值，高層戰略）
AI 的貢獻：執行（100% 價值，技術實現）

✅ 優勢：你做最有價值的工作，AI 做重複工作
```

## 💡 為什麼只給定義書不給代碼？

### 原因 1：尊重你的時間
- 給代碼 = 讓你花時間「改代碼」（低價值）
- 給定義書 = 讓你花時間「思考問題」（高價值）

### 原因 2：尊重你的智力
- 給代碼 = 把你當「用戶」（被動消費）
- 給定義書 = 把你當「設計師」（主動創造）

### 原因 3：尊重你的未來
- 給代碼 = 你只能用這一個系統
- 給定義書 = 你能設計**無限個** Workflow（投資、HR、採購、審核...）

### 原因 4：尊重 AI 的能力
```
代碼編寫   = AI 的基礎工作 ← 為什麼讓你做？
架構設計   = AI 的高級工作 ← 為什麼讓你做？
問題定義   = 人類獨有的工作 ← 這才是你應該做的
```

### ❓ Ultracode 常見問題速解

**Q：「Ultracode 我的定義書+預算書」這句話是幹什麼的？**
A：這是激活指令。系統識別後會自動進入 Dynamic Workflow 模式，先展示計畫（不執行）。

**Q：系統怎麼知道我的定義書和預算書是什麼？**
A：因為你在下面貼上了。系統會讀取你貼上的內容，理解你的需求。

**Q：「Ultracode 我的定義書+預算書」的順序重要嗎？**
A：不重要。順序隨意，系統會自動識別。你也可以說「Ultracode，看我的定義書和預算書」。

**Q：這個指令會立即執行代碼嗎？**
A：不會。它只展示計畫。只有你說「確認執行」，才會開始消耗 Token。

**Q：Ultracode 免費嗎？**
A：完全免費（規劃階段）。只有你說「確認執行」後，才開始計費。計費規則和舊版本完全相同。

**Q：Ultracode 和舊 Claude Code 有什麼區別？**
A：只是進入方式和指令模式不同。計費規則、計算能力、支持的功能都完全相同。

**Q：我一定要用 Ultracode 指令嗎？**
A：不一定。你也可以手動寫提示詞。但 Ultracode 指令更簡潔、更快速、更不容易出錯。

**Q：如果我輸入了 Ultracode 指令但改主意了，怎麼辦？**
A：在系統展示計畫後，你可以說「取消」。零成本，安全退出。或說「需要修改」，系統重新規劃（還是免費）。

**Q：定義書和預算書要貼在哪裡？**
A：就在「Ultracode 我的定義書+預算書」這句話下面，用 Markdown 代碼塊或直接貼上都可以。

**Q：Ultracode 支持離線使用嗎？**
A：不支持。Ultracode 是線上工具，需要網絡連接。但你可以下載定義書文件本地保存，之後聯網時再用。
