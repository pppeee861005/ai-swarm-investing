# 🚀 什麼是 Dynamic Workflows？

**一句話定義**：Dynamic Workflows 是由 Claude Code 提供的功能，讓你通過**定義問題和預算**，自動生成和執行優化的 AI 工作流。

**核心區別**：
- ❌ 舊方式：你寫代碼，機器執行代碼
- ✅ 新方式：你定義問題，AI 設計方案，自動執行

---

## 第一章：核心概念

### 🎯 Dynamic Workflows 的三個角色

```
     定義問題           設計方案              執行方案
       你        →       AI       →        Claude Code
     (人類)    (思考)   (設計)    (執行)    (完成)

     預算與          確定最優          監控成本
     約束條件        架構與參數        實時反饋
```

### 📋 你需要提供的三樣東西

#### 1️⃣ **問題定義**（Problem Statement）

清晰地描述你想解決什麼問題。

**例子**：
```
「監控我選中的 20 支股票，當出現買入信號時提醒我。」

不是：「幫我寫一個股票監控系統」
而是：「監控 + 買入信號 + 實時提醒」
```

**為什麼重要**？
- 問題定義得好 → AI 能設計出對的方案
- 問題定義得模糊 → AI 浪費 Token 在探索和修正

#### 2️⃣ **成功指標**（Success Criteria）

定義什麼算是「成功完成」。

**例子**：
```
監控股票的成功標準：
✅ 能檢測到 95% 的買入信號
✅ 誤報率 < 5%（不要天天發假信號）
✅ 反應時間 < 10 秒（不要股票都漲完了才提醒）
✅ 每月成本 < 5 美金（可控的支出）
```

**為什麼重要**？
- 沒有指標 → AI 不知道該優化什麼
- 有清晰指標 → AI 有目標，能自動優化

#### 3️⃣ **預算**（Budget）

定義你願意花多少 Token 來解決這個問題。

**例子**：
```
完成一個股票驗證：
- 預期成本：0.12 單位 = 120 萬 Token
- 應急預留：0.13 單位 = 130 萬 Token
- 總預算：0.25 單位 = 250 萬 Token
```

**為什麼重要**？
- Token = 真實成本（美金）
- 預算約束 → AI 會自動優化效率
- 沒有預算約束 → AI 可能過度設計

## 第二章：Dynamic Workflows 怎麼運作

### 🔄 完整工作流程

```
第 1 步：你提供「定義書」
       ├─ 問題定義
       ├─ 成功指標
       ├─ 決策規則
       └─ 預算

       ↓

第 2 步：Claude Code 分析定義書
       ├─ 理解問題的本質
       ├─ 識別關鍵決策點
       └─ 評估技術複雜度

       ↓

第 3 步：Claude Code 設計最優方案
       ├─ 決定應該分成幾個 Stage（階段）
       ├─ 決定每個 Stage 應該做什麼
       ├─ 決定 Stage 間的並行或串行
       └─ 決定監控和降級策略

       ↓

第 4 步：Claude Code 自動生成代碼
       ├─ 根據設計方案生成執行代碼
       ├─ 嵌入成本監控邏輯
       └─ 嵌入降級和升級條件

       ↓

第 5 步：Claude Code 執行工作流
       ├─ 實時監控成本消耗
       ├─ 如果超支，自動觸發降級
       ├─ 完成後生成報告
       └─ 報告包含成本、結果、優化建議

       ↓

第 6 步：你審視結果
       ├─ 結果是否滿足成功指標
       ├─ 成本是否在預算內
       └─ 是否需要調整定義書重新運行
```

### 💡 Dynamic Workflows 自動做的事

**Claude Code 會自動決定**：

1. **工作流的並行度**
   ```
   問題：監控 20 支股票，檢查 50 個指標

   選項 A：串行（一個接一個）
   → 耗時 20 分鐘，但成本低

   選項 B：並行（同時進行）
   → 耗時 2 分鐘，但成本高

   → Claude Code 根據你的預算和時間要求自動選擇
   ```

2. **數據搜集的優先級**
   ```
   問題：需要 100 個數據點，但預算有限

   → Claude Code 自動識別「最重要的 60 個數據點」
   → 先搜集它們，如果還有預算再搜集其他
   → 確保永遠不會因為數據不全而無法決策
   ```

3. **何時降級**
   ```
   預算：0.25 單位

   檢查點 1：成本 0.05，進度 20%，正常 ✅
   檢查點 2：成本 0.15，進度 60%，接近預期 ✅
   檢查點 3：成本 0.20，進度 80%，已超 80% → 觸發降級 ⚠️

   降級行動：減少詳細分析，保留關鍵結論

   完成：成本 0.24，進度 100%，在預算內 ✅
   ```

4. **何時升級**
   ```
   發現一個重大風險信號
   → 這值得追加 Token 進行深度分析
   → Claude Code 評估：「升級成本 0.02」「收益很高」
   → 自動追加分析，給出更完整的風險評估
   ```

## 第三章：Dynamic Workflows vs 傳統方式

### 📊 三個維度對比

#### 維度 1：你的角色

| 傳統方式 | Dynamic Workflows |
|---------|------------------|
| 寫代碼或選擇軟體 | 定義問題和預算 |
| 花時間在技術細節 | 花時間在問題理解 |
| 需要懂代碼 | 只需要懂自己的領域 |
| 改一點要改很多代碼 | 改定義書，自動重新設計 |

**人類的價值轉向**：
```
❌ 不再是「執行能力」（寫代碼、操作系統）
✅ 轉向「定義能力」（清晰思考、精準決策）

換句話說：機器做執行，人做思考。
```

#### 維度 2：AI 的角色

| 傳統方式 | Dynamic Workflows |
|---------|------------------|
| 執行你的指令 | 根據問題設計最優方案 |
| 被動等待 | 主動優化 |
| 按部就班執行 | 邊執行邊監控邊調整 |
| 無法自動降級 | 自動識別超支並降級 |

**AI 的角色升華**：
```
❌ 不再是「機械執行者」（按指令做）
✅ 升華到「智慧設計師」（根據約束優化方案）

換句話說：AI 不只會做，還會想。
```

#### 維度 3：整個流程

| 傳統方式 | Dynamic Workflows |
|---------|------------------|
| 代碼 → 執行 → 結果 | 定義 → 設計 → 執行 → 監控 → 優化 |
| 靜態的、固定的 | 動態的、自適應的 |
| 質量難以保證 | 質量由預算決定 |
| 成本難以預測 | 成本透明可控 |

## 第五章：怎麼開始使用 Dynamic Workflows

### 🚀 三步快速開始

#### 第 1 步：選擇一個計劃7的場景

```
我想監控股票買入信號
  → 選擇「蜂群覺醒」

我想驗證某支股票的買點
  → 選擇「三維獵殺」

我想知道市場情況變了要怎麼調整
  → 選擇「自動校準」

我想發現風險信號
  → 選擇「新聞獵手」
```

#### 第 2 步：閱讀定義書

```
讀懂：
✅ 這個場景要解決什麼問題
✅ 成功的標準是什麼
✅ 怎麼執行

修改你需要的：
✅ 你特別關心的指標
✅ 你的風險偏好
✅ 你的預算約束
```

#### 第 3 步：告訴 Claude Code

```
「我想用『蜂群覺醒』，監控這 20 支股票：XXXXX」

Claude Code 會：
1. 分析你的需求
2. 根據定義書設計執行方案
3. 自動生成并執行代碼
4. 監控成本
5. 給出結果報告
```

### 💡 一個完整例子

**你**：
```
我想驗證股票 AAAA，用「三維獵殺」定義書。
我打算買的價位是 150 元。
我特別關心現金流指標。
預算預留是 0.25 單位。
```

**Claude Code 做的事**：
```
✅ 步驟 1：搜集 AAAA 的財務、技術、市場數據
         成本：0.03 單位

✅ 步驟 2：分析財務面（特別深入分析現金流）
         成本：0.03 單位

✅ 步驟 3：分析技術面
         成本：0.02 單位

✅ 步驟 4：分析市場面
         成本：0.02 單位

⚠️ 進度檢查：已消耗 0.10，預期成本達到，進入節省模式

✅ 步驟 5：整合報告
         成本：0.01 單位

✅ 完成：總成本 0.11 單位（在預算 0.25 內）

結果：
「AAAA 在 150 元的買點質量為『中強』，
 風險級別為『中等』，
 建議：可以買入，但控制倉位。」
```

**你**：根據報告決策
```
決定：分批建倉
方案：第一批 50%，第二批等回調再買 50%
```

## 第六章：Dynamic Workflows 的三個境界

### 🌱 第一境界：跟著定義書做

```
你的角色：用戶
流程：選場景 → 讀定義書 → 提需求 → 得結果

好處：
✅ 簡單直接
✅ 快速決策

限制：
❌ 只是在用別人的方案
❌ 沒有學習設計方法
```

### 🌿 第二境界：根據需要改定義書

```
你的角色：定製者
流程：選場景 → 理解定義書 → 修改決策規則 → 提需求 → 得結果

好處：
✅ 定制化方案
✅ 開始學習「怎麼定義問題」

限制：
❌ 只能修改現有場景
❌ 無法設計全新場景
```

### 🌳 第三境界：自己設計 Dynamic Workflow

```
你的角色：設計師
流程：遇到新問題 → 設計定義書 → 提給 Claude Code → 自動生成方案

好處：
✅ 完全掌握方法論
✅ 能設計任何領域的 Workflow（不只投資）

達成方式：
❌ 需要深入理解 Dynamic Workflows 框架
✅ 參考計劃7的例子學習設計方法
✅ 看「怎麼用計劃7的範例.md」
```

**我們的目標是讓你進入第三境界。**

## 第七章：常見問題

### ❓ Q1：Dynamic Workflows 能做什麼？

**A**：任何需要決策、監控、優化的流程。

```
投資領域：
✅ 監控買入信號（蜂群覺醒）
✅ 驗證買點質量（三維獵殺）
✅ 發現新聞風險（新聞獵手）

非投資領域（理論上可行）：
✅ HR：監控員工離職風險
✅ 採購：監控供應鏈異常
✅ 合規：監控政策變化風險
✅ 市場：監控競爭對手動向
✅ 產品：監控用戶行為變化
```

### ❓ Q2：Dynamic Workflows 和傳統代碼生成有什麼區別？

| 傳統代碼生成 | Dynamic Workflows |
|------------|------------------|
| 「幫我寫一個監控系統」 | 「監控 20 支股票，檢測 95% 信號」 |
| AI 生成代碼，你去用 | AI 設計方案，自動執行，邊執行邊優化 |
| 靜態執行 | 動態優化（自動降級、升級） |
| 成本難以控制 | 預算約束，成本透明 |

### ❓ Q3：預算怎麼估算？

**A**：看問題複雜度：

```
簡單問題（快速檢查、單維度分析）：
  → 預算：0.08-0.15 單位

中等問題（多維度分析、決策驗證）：
  → 預算：0.15-0.30 單位

複雜問題（深度分析、多角度對標）：
  → 預算：0.30-0.50 單位

超複雜問題（極端情景、全面評估）：
  → 預算：0.50+ 單位
```

**經驗法則**：
```
投資金額 vs 驗證成本

100 元試驗 → 預算 0.05（幾毛錢）
10,000 元決策 → 預算 0.15-0.25（1-5 美金）
100,000 元大額 → 預算 0.30-0.50（3-8 美金）
```

### ❓ Q4：可以自己設計 Dynamic Workflow 嗎？

**A**：完全可以！這是最終目標。

```
步驟 1：選擇一個計劃7的定義書作為範本
       （比如「三維獵殺」）

步驟 2：理解其 8 章結構

步驟 3：用同樣的 8 章結構設計你的新 Workflow
       （比如「人才獵手」進行人才評估）

步驟 4：把定義書提給 Claude Code
       → AI 自動設計方案、生成代碼、執行

步驟 5：根據結果優化定義書

→ 這就是完整的 Dynamic Workflows 設計流程
```

詳見「怎麼用計劃7的範例.md」中的「進階：自己設計」部分。

## 核心心法

> **Dynamic Workflows 的本質是：**
>
> **把你從「執行者」解放出來，**
> **讓你可以成為「設計者」。**
>
> 你不再需要寫代碼、選軟體、學工具。
>
> 你只需要：
> 1️⃣ 清晰地定義問題
> 2️⃣ 設定成功標準
> 3️⃣ 決定可用的預算
>
> 剩下的，讓 AI 去做。
>
> **這就是 Software 3.0 時代的開始。**

### 🌟 重要提醒

**你生成的每一個 Dynamic Workflows 都不只是個人資產，更是人類知識的寶貴財富。**

#### 三個行動

**1️⃣ 保存你的定義書**

當你用 Claude Code 設計和執行了一個 Workflow，不要讓它消失在對話記錄中。

```
保存為：定義書_[Workflow名稱]_v[版本].md

好處：
✅ 下次可以快速複用（不用重新設計）
✅ 可以追蹤版本演進（v1 vs v2 的改進）
✅ 可以為他人提供參考
```

**2️⃣ 精進你的定義書**

執行一次不夠，用它 3-5 次，不斷改進。

```
改進週期：
執行 1 → 檢驗結果 → 調整定義書
   ↓
執行 2 → 檢驗結果 → 調整定義書
   ↓
...

經過 3-5 次，你的 Workflow 會變得越來越精準。
```

**3️⃣ 分享你的定義書**

一個人的力量有限，一群人的力量無限。

```
分享途徑：
✅ 分享給你的團隊（讓團隊受益）
✅ 分享給社群（貢獻計劃7 生態）
✅ 寫成文章（啟發更多人）

✅ DO：署名原作者，記錄改進者

❌ DON'T：聲稱別人設計的是自己的
❌ DON'T：鎖定 Workflow，不讓他人使用
```
