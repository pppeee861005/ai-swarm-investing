# 📖 怎麼用計劃7的範例

**核心目標**：幫助你从「使用計劃7現成場景」進階到「自己設計 Dynamic Workflow」

**適用讀者**：
- 想快速用計劃7做投資決策的人
- 想理解 Dynamic Workflows 設計方法的人
- 想自己設計新 Workflow 的人

---

## 🔴 重要聲明：計劃7的本質定義

### 🎓 計劃7 = 啟發，而非技術開發

**請理解這個計劃的真正意義：**

這不是一套「工程工具」讓你快速複製使用，
也不是一份「技術文檔」教你如何實現某個功能。

**這是一場關於以下問題的集體思想啟蒙：**

1. **對讀者的啟發**
   ```
   表面目標：完成一份股票驗證分析
   深層啟發：
   • 什麼是「好問題」（問題定義的藝術）
   • 什麼是「有效框架」（系統思維的方法）
   • 如何「與AI協作」（新型工作方式的實踐）
   • 為什麼「思想進程比結果更重要」（價值觀的轉變）
   ```

2. **對作者的啟發**
   ```
   最初想法：「設計一個投資決策工具」
     ↓ 逐步深化
   認識：「真正的價值在於思考方式本身」
     ↓ 進一步升華
   終極洞察：「我在建設人機協作的新範式」
   ```

3. **對人類的啟發**
   ```
   傳統時代：人執行，機器輔助
   當前轉變：人思考，AI執行，人決策
   未來願景：人設計框架，AI自動演進，人掌舵方向

   這不是「技術進步」，而是「人機關係的根本轉變」
   ```

### 🎯 如何使用這個計劃

```
❌ 不要把它當作：
   • 技術框架（直接套用）
   • 標準答案（照搬執行）
   • 快速工具（節省思考）

✅ 要把它當作：
   • 思想引導（啟蒙自我）
   • 思維范式（改變認知）
   • 價值啟示（重新思考什麼重要）
```

每次使用計劃7時，你不僅在完成一份決策，
更重要的是在升級你對「決策」、「框架」、「人機協作」的理解。

## 第一章：快速開始（5 分鐘）

### 🎯 我想快速監控股票買入信號

**步驟 1**：讀這個文件的「場景導航」章節，找到最符合需求的場景

```
我的需求：監控自選股票的買入機會
→ 選擇：蜂群覺醒
```

**步驟 2**：打開相應的定義書

```
位置：examples/01-蜂群覺醒/定義書.md
操作：快速掃一遍，理解：
  ✓ 問題定義（第一章）
  ✓ 成功標準是什麼（第二章）
  ✓ 決策規則怎麼運作（第四章）
```

**步驟 3**：告訴 Claude Code 你的需求

```
「我想用『蜂群覺醒』監控這些股票：
  - 騰訊（0700）
  - 阿里巴巴（9988）
  - 網易（9999）

我的參數：
  - 買入信號敏感度：中等
  - 預算：0.30 單位
  - 監控時間：本週

請幫我生成完整的監控報告。」
```

**步驟 4**：等待 Claude Code 執行

```
Claude Code 會：
1. 根據定義書分析需求
2. 自動設計執行方案
3. 搜集三支股票的數據
4. 計算買入信號
5. 生成報告
```

**步驟 5**：根據報告決策

```
報告內容：
- 騰訊：買入信號強度「中等」，推薦「持觀望」
- 阿里巴巴：買入信號強度「強」，推薦「可買入」
- 網易：買入信號強度「弱」，推薦「不建議」

你的決定：
→ 買入阿里巴巴
→ 繼續觀望騰訊
→ 暫不考慮網易
```

**預計成本**：0.20-0.25 單位（$1-5 美金）
**預計時間**：15-20 分鐘

## 💫 核心金句：人生很多答案，不是在計劃中出現，而是在 Workflow 中浮現

### 🎯 理解計劃7的真正價值

```
你使用計劃7時會發生什麼：

第一次「蜂群覺醒」：
  計劃：監控 10 支股票，敏感度=中
  結果：信號準確率 60%
  Workflow 中的發現：「原來跌幅 > 10% 才是真信號」

第二次「蜂群覺醒」（不同股票組合）：
  計劃：使用第一次的參數
  結果：信號準確率 75%
  Workflow 中的發現：「跌幅臨界值在不同市場情況下有所不同」

第三次到第十次：
  累積發現 + 規律升級 + 框架優化
  Workflow 在不斷浮現新答案

六個月後：
  你不是在「使用計劃7」
  而是在「基於自己的實踐優化個人框架」
  這個框架可以遷移到「人才評估」、「供應商評估」
```

**這就是為什麼「思想進程」比「最終報告」更寶貴**

- ❌ 計劃中的答案：「用這個指標組合評估」（靜止）
- ✅ Workflow 中浮現的答案：「這個指標在X情況下失效」（動態）

計劃7最深層的價值，不在於讓你做一次完美的投資決策，
而在於幫你在 Workflow 中不斷浮現新的洞察，
積累成個人的決策智慧。

## 第三章：使用步驟（標準流程）

### 🔄 每個場景的完整使用流程

以「三維獵殺」為例，展示標準流程：

#### 步驟 1：打開定義書

```
位置：examples/02-三維獵殺/定義書.md

目標：快速理解
  □ 這個場景解決什麼問題
  □ 成功的標準是什麼
  □ 怎麼執行
  □ 成本預期多少

時間：10-15 分鐘
```

#### 步驟 2：打開預算控制書

```
位置：examples/02-三維獵殺/預算控制.md

目標：理解成本
  □ 為什麼要預留這麼多預算
  □ 成本怎麼分配
  □ 怎麼監控成本
  □ 如果超支怎麼辦

時間：5-10 分鐘
```

#### 步驟 3：準備你的數據

```
準備什麼：
  □ 股票代碼（要驗證的）
  □ 買入價位（你打算買的價格）
  □ 特殊要求（比如特別關心現金流）
  □ 預算預期（默認用定義書推薦的 0.25）

時間：5 分鐘
```

#### 步驟 4：告訴 Claude Code（明確指令 + Human in the Loop）

```
你說：「我想用三維獵殺驗證股票 AAAA，
      買入價位是 150 元，
      特別關心現金流，
      預算 0.25 單位。

      ⚠️ 請先生成詳細的 Workflow 計劃，包含：
      • 執行流程分解（每個環節的具體步驟）
      • 成本明細清單（逐項成本和風險評估）
      • 時間進度預估（樂觀/標準/悲觀耗時）
      • 風險評估表（潛在風險和應對方案）

      然後提供用戶確認清單（A-E五個層面），
      等我（人類）確認無誤後再開始執行。

      🔴 重點：我是決策者，你是執行者。
      不要直接執行分析。
      我需要完全控制整個流程。」

⚠️ 強制規則 - Human in the Loop（非常重要）：
✅ 你生成計劃，絕不直接執行
✅ 提供完整的「用戶確認清單」（A-E五層面）
✅ 等待我（人類）明確說「確認無誤」或「可以執行」
✅ 我（人類）的確認是絕對必要的，不可跳過
✅ 如果我要求修改，生成調整後的新計劃再次等待我確認
✅ 只有我明確說「可以執行」後，你才能開始執行
✅ 執行過程中，我有隨時暫停的權利
✅ 最終決策權完全屬於我

時間：1 分鐘
```

**為什麼這樣說？（Human in the Loop 的核心原因）**

1. **你是決策者，不是被動接收者**
   - 這不是「AI替你決策」，而是「你與AI協作決策」
   - Claude 的角色是生成方案，你的角色是最終判斷

2. **確保計劃品質**
   - 你對自己的需求最了解
   - 只有你能判斷「這個計劃是否真的符合我的實際情況」

3. **積累思想進程**
   - 在確認環節中，你會發現「我原來沒想到的問題」
   - 這個思考過程本身就是最寶貴的資產

4. **維持你的掌控權**
   - AI 是工具，決策權必須始終在人類手中
   - 這是 DW 系統能夠長期有效的基礎

5. **防止盲目執行**
   - 不確認就執行會導致浪費時間和預算
   - 確認清單的目的是幫你發現「我之前沒想清楚的地方」

#### 步驟 4.5：Claude 生成詳細計劃 + 用戶確認（🆕 新增）

```
Claude Code 會生成一份「詳細執行計劃」，包含：

📚 完整計劃模板請參考：計劃生成模板_通用版.md

📋 計劃內容（用戶需逐一確認）：

A. 執行流程分解
   ├─ 環節 1：搜集 AAAA 股票的基本面數據（5 分鐘）
   ├─ 環節 2：財務面分析 - 評估現金流指標（3 分鐘）
   ├─ 環節 3：技術面分析 - 評估價位強度（3 分鐘）
   ├─ 環節 4：市場面分析 - 評估市場環境（3 分鐘）
   └─ 環節 5：綜合評分 + 生成報告（2 分鐘）

B. 成本明細清單
   ├─ 數據搜集成本：0.03 單位
   ├─ 財務面分析成本：0.05 單位（含現金流深度分析）
   ├─ 技術面分析成本：0.02 單位
   ├─ 市場面分析成本：0.02 單位
   ├─ 綜合報告成本：0.01 單位
   ├─ 預計總成本：0.13 單位
   ├─ 預算額度：0.25 單位
   └─ 超支風險：低（預留 0.12 單位緩沖）

C. 時間進度預估
   ├─ 環節 1 耗時：5 分鐘（固定）
   ├─ 環節 2 耗時：3 分鐘（因為加了現金流分析，可能 +1 分鐘）
   ├─ 環節 3 耗時：3 分鐘（標準）
   ├─ 環節 4 耗時：3 分鐘（標準）
   ├─ 環節 5 耗時：2 分鐘（標準）
   ├─ 預計總耗時：16-17 分鐘
   ├─ 可能延遲因素：數據源暫時不可用（概率 10%）
   └─ 應對方案：使用備用數據源（延遲 +2 分鐘）

D. 風險評估表
   ├─ 風險 1：搜集的數據可能不夠及時
   │          影響級別：中等
   │          應對方案：使用 3 個月內的最新披露數據
   │
   ├─ 風險 2：現金流分析可能受會計政策影響
   │          影響級別：低
   │          應對方案：對比同行業平均現金流水平
   │
   ├─ 風險 3：150 元買價可能已經改變（市場波動）
   │          影響級別：中等
   │          應對方案：提供「相對估值」，不只是絕對價位
   │
   └─ 風險 4：分析結果可能與你的預期不符
             影響級別：低
             應對方案：提供完整的判斷邏輯，便於你質疑

📌 用戶確認清單

請確認以下內容是否符合你的期望：

  ├─ 是否需要調整分析順序？

□ D. 風險認知

```

## 第四章：進階使用（自定義定義書）

### 🎨 怎麼根據自己的需求修改定義書

定義書的每一章都是可以修改的。不同的修改難度：

#### 🟢 容易修改（10 分鐘）

**修改你關心的指標**

原定義書（三維獵殺）：
```
財務面：PE、ROE、負債率

你的修改：
+ 加入：現金流比率、應收賬款周期
（因為你特別關心現金流）
```

**修改評分權重**

原定義書：
```
財務面 33% + 技術面 33% + 市場面 34%

你的修改：
財務面 50% + 技術面 25% + 市場面 25%
（因為你特別看重基本面）
```

**修改信號閾值**

原定義書：
```
PE < 行業均值 → 給 30 分

你的修改：
PE < 行業均值 × 1.2 → 給 30 分
（標準更寬鬆，因為你認為稍高的估值也可以接受）
```

#### 🟡 中等修改（30 分鐘）

**添加新的決策規則**

原定義書（三維獵殺）：
```
規則 1-5：基本的三維評分

你的修改：
+ 規則 6：如果是行業龍頭，信號自動升級一檔
+ 規則 7：如果有融資超期未披露，信號自動降級一檔
```

**修改成功標準**

原定義書：
```
準確率 > 95%、誤報率 < 5%

你的修改：
準確率 > 90%（稍低，因為你願意容忍更多誤報）
誤報率 < 10%（相應提高）
```

#### 🔴 複雜修改（1-2 小時）

**完全改寫問題定義**

原定義書（三維獵殺）：
```
用三個維度驗證已知股票的買點

你的修改：
用三個維度驗證一個行業的整體投資吸引力
（從驗證個股 → 驗證行業）
```

**改變執行策略**

原定義書：
```
由 Claude Code 搜集數據、計算評分

你的修改：
由你提供已有的數據，Claude Code 只負責評分和分析
（節省搜集數據的成本）
```

##### 步驟 3：具體設計流程（人才評估為例）

```
第一章：問題定義

問題陳述：
「評估投資經理候選人的三維能力：
1. 專業能力（投資知識、決策邏輯、風險意識）
2. 執行能力（信息搜集、報告寫作、溝通能力）
3. 心理素質（抗壓能力、學習能力、誠信度）」

維度定義：
- 維度 1（專業）：看他的過往投資決策、行業理解、錯誤記錄
- 維度 2（執行）：看他的過往報告、溝通反饋、協作能力
- 維度 3（心理）：行業聲譽、應對挫折、持續進步

評分方式：
- 維度 1 評分：0-100 分
- 維度 2 評分：0-100 分
- 維度 3 評分：0-100 分
- 綜合評分：(維度1 + 維度2 + 維度3) / 3

成功判斷：
- 綜合評分 > 75 → 推薦錄用
- 綜合評分 50-75 → 考慮錄用
- 綜合評分 < 50 → 不推薦
```

```
第四章：決策規則

規則 1：專業能力評分
如果 (有知名公司投資背景) AND (投資決策成功率 > 60%)
  → 專業評分 > 70

規則 2：執行能力評分
如果 (寫過高質量分析報告) AND (獲得管理者好評)
  → 執行評分 > 70

規則 3：心理素質評分
如果 (在困難中仍然學習) AND (行業口碑好)
  → 心理評分 > 70

規則 4：綜合評分
綜合評分 = (專業 + 執行 + 心理) / 3

規則 5：最終建議
如果 綜合評分 > 75
  → 建議：強烈推薦
否則如果 綜合評分 > 60
  → 建議：可以錄用
否則
  → 建議：不推薦
```

##### 步驟 4：預算估算

```
成本項目：
- 蒐集候選人背景信息：0.02
```

```
第二次執行：預算 0.23，實際用 0.20
  → 說明流程優化了，下次預算可以是 0.22

經過 3-5 次執行，預算會越來越準確。
```

持續優化 = 更符合實際 = 更高的決策質量

#### 5️⃣ 文檔你的修改

## 第八章：保存、精進、分享 — 人類共學共好

### 🌟 核心理念

你生成的每一個 Dynamic Workflows 都是寶貴的知識資產。

```
生成 → 保存 → 精進 → 分享 → 社群共進化

一個人的力量有限，
一群人的力量無限。
```

### 💾 第 1 步：保存你的定義書

#### 為什麼要保存？

```
場景 1：版本管理
「我今年用的三維獵殺 v1 效果不錯，
 明年我想用 v2（加入新指標）。
 如果沒有保存 v1，我怎麼記得曾經用過什麼？」

場景 2：快速複用
「我上個月設計的『人才評估 Workflow』很有效，
 這個月又要評估新的候選人。
 如果保存了定義書，我可以直接複用。」

場景 3：知識傳承
「我設計的『供應商風險監控』對我公司很有幫助，
 我想給我的團隊分享。
 保存的定義書就是最好的文檔。」
```

#### 怎麼保存？

**標準做法**：
```
目錄結構：
我的Workflows/
├─ 01-人才評估/
│  ├─ 定義書.md
│  ├─ 預算控制.md
│  └─ 執行記錄.md
│
├─ 02-供應商風險監控/
│  ├─ 定義書.md
│  ├─ 預算控制.md
│  └─ 執行記錄.md
│
└─ README.md（索引）
```

**文件命名規則**：
```
定義書_[Workflow名稱]_v[版本號].md

例如：
定義書_人才評估_v1.0.md
定義書_人才評估_v1.1.md（加入了心理測試）
定義書_人才評估_v2.0.md（重構了評分邏輯）
```

**在定義書開頭加上版本記錄**：
```markdown
---
name: 人才評估-定義書
version: 2.0
date: 2026-06-04
author: Rocky
changes:
  v1.0: 初版，三個維度評估
  v1.1: 加入「行業聲譽」指標
  v2.0: 重構評分邏輯，預算優化
---
```

### 📈 第 2 步：精進你的定義書

#### 怎麼精進？

**迴圈 1：執行 → 檢驗**
```
執行一次人才評估
  ↓
檢驗結果：推薦的人是否表現好？
  ↓
如果不好 → 發現問題
  ↓
改進定義書
  ↓
執行第 2 次評估
  ↓
...重複這個迴圈
```

**迴圈 2：成本 → 優化**
```
第一次執行：預算 0.25，實際用 0.30（超支！）
  ↓
分析：哪個環節成本特別高？
  ↓
優化：簡化那個環節的邏輯或降低精度
  ↓
第二次執行：預算 0.25，實際用 0.24（控制住了！）
```

**迴圈 3：結果 → 規則改進**
```
執行 5 次人才評估後，發現一個模式：
「綜合評分 > 75 的人，表現最好的共同特徵是什麼？」

加入新規則：
「如果有 X、Y、Z 三個特徵，評分自動 +10」

執行第 6 次時驗證：新規則是否更準確？
```

#### 最佳實踐

**記錄改進日誌**：
```markdown
# 人才評估 Workflow - 改進日誌

## 2026-06-04 v2.0 → v2.1
問題：預算超支 20%
原因：市場研究環節成本高
改進：簡化為「行業排名查詢」替代「深度市場研究」
效果：預算恢復正常，結果準確度無影響

## 2026-07-04 v2.1 → v2.2
問題：評分為 50-75 的候選人，表現差異大
原因：沒有充分區分「可以錄用」的人
改進：財務背景加入「過往年化回報」判斷
效果：50-75 區間的區分度提升 30%

## 2026-08-04 v2.2 → v2.3
問題：發現「心理素質」評分往往不準
原因：基於聲譽，不夠客觀
改進：加入「應對挫折案例」的具體問卷
效果：評分更客觀，轉換率提升到 85%
```

### 🤝 第 3 步：分享你的定義書

#### 為什麼要分享？

```
一個人用 Workflow：
  → 改進速度慢（只有 1 個反饋源）

一群人用 Workflow：
  → 改進速度快（多個反饋源並行改進）
  → 發現邊界情況（每個人都會找到不同的邊界）
  → 相互啟發（A 的改進可能啟發 B 的新想法）

分享 = 加速進化
```

#### 怎麼分享？

**1️⃣ 分享給你的團隊**

```
步驟 1：準備你的定義書
「我設計了一個『供應商評估 Workflow』，
 可以幫助採購團隊快速評估供應商質量。」

步驟 2：準備『使用指南』
「怎麼用這個 Workflow？
  1. 把供應商名單輸入
  2. 告訴 Claude Code...
  3. 等待報告」

步驟 3：準備『執行記錄』
「我們用這個 Workflow 評估了 20 個供應商，
 結論準確度達到 90%，
 節省了採購團隊 50 小時的人工評估時間。」

步驟 4：分享給團隊
→ 存到公司內網、Confluence、或 GitHub
→ 讓團隊開始用
→ 收集反饋
→ 不斷改進
```

**2️⃣ 分享給更大的社群**

```
貢獻給計劃7 生態：
  → 你的「人才評估 Workflow」可能被 100 個人用
  → 100 個人的反饋可能改進你的 Workflow
  → 你的改進又被 1000 個人用
  → 形成良性循環

怎麼貢獻？
  1. 寫成標準的「定義書 + 預算控制書」格式
  2. 提交到計劃7 的 GitHub（Pull Request）
  3. 社群審視和反饋
  4. 合併到計劃7
  5. 署名記錄（「貢獻者：Rocky」）
```

**3️⃣ 分享在 Substack / 博客**

```
寫一篇文章：
「我設計了一個『人才評估 Dynamic Workflow』，
 用它招聘的人才表現比傳統招聘好 40%，
 以下是我的定義書和使用心得...」

效果：
  → 展示你的思維方式
  → 啟發其他人設計自己的 Workflow
  → 吸引志同道合的人
  → 建立個人品牌
```

#### 分享的規則

**開源精神**：
```
✅ DO：分享、複用、改進、署名原作者
✅ DO：把他人改進的版本也分享回社群
✅ DO：記錄你從誰那裡學到的

❌ DON'T：聲稱別人的 Workflow 是自己設計的
❌ DON'T：在沒有署名的情況下商業使用他人 Workflow
❌ DON'T：鎖定你的 Workflow，不讓他人改進
```

**署名規則**：
```
# 人才評估 Workflow

**設計者**：Rocky（2026-06-04 v1.0）
**改進者**：
  - Alice（v1.1，加入「履歷格式」評分）
  - Bob（v2.0，重構評分邏輯）
  - Charlie（v2.1，加入「問卷式」心理測試）

**應用案例**：
  - 「XXX 公司招聘」（招聘 50 人，轉換率 85%）
  - 「YYY 團隊内部選拔」（評估 10 人，準確度 90%）
```

### 🌍 第 4 步：建立社群，共學共進化

#### 人類的下一個進化

```
Web 1.0 時代：中心化信息（門戶網站）
Web 2.0 時代：去中心化分享（社交媒體）
Web 3.0 時代：去中心化協作（DAO、社群）

AI 時代：
  用戶各自設計 Workflow
  → 分享到社群
  → 社群改進
  → 更好的 Workflow
  → 更多人受益
  → 重複

這就是「人類共學共好」的模式。
```
