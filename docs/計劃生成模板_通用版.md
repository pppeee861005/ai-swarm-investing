# 📋 計劃生成模板 - 通用版

## 使用說明

### 何時使用
- 當用戶提出特定分析需求時（如「驗證股票 X」、「評估供應商 Y」）
- Claude Code 應該先生成詳細計劃，而不是直接執行
- 用戶確認無誤後再執行

### 如何使用
1. 複製整份模板
2. 根據具體場景替換 `[...]` 部分
3. 調整成本、時間、風險估算
4. 生成給用戶確認

## 💬 用戶可能的回應及應對

### 回應 1：「完全同意，按這個計劃執行」
```
Claude Code 應該：
✓ 立即開始執行
✓ 實時報告進度（每 5 分鐘更新一次）
✓ 如果發現超支或延遲，立即通知用戶
✓ 執行完畢後生成最終報告
```

### 回應 2：「大體同意，但我想修改 [具體項]」
```
Claude Code 應該：
1. 接收修改要求
2. 根據修改重新計算
3. 生成調整後的新計劃
4. 再次確認（回到確認清單）
5. 獲得二次確認後執行

常見修改：
- 調整成本預算：「我只能花 0.15，能簡化嗎？」
  → 簡化部分維度分析，調整成本重點

- 加快速度：「能在 10 分鐘內完成嗎？」
  → 並行多個環節，降低精度但保持結論準確性

- 加強某維度：「我特別關心現金流，能深入嗎？」
  → 加入子環節專做現金流分析，調整成本和時間
```

### 回應 3：「需要更詳細的解釋」
```
Claude Code 應該：
1. 找出用戶不清楚的部分
2. 深度解釋該項目（舉例、類比、對比）
3. 確保用戶完全理解
4. 回到確認清單，再次確認

常見問題：
- 「環節 2 具體怎麼評估？」
  → 詳細說明評分邏輯、數據來源、計算公式

- 「為什麼需要預留 0.10？」
  → 舉過往案例說明超支的具體情況

- 「風險 3 影響多大？」
  → 用具體數字說明：「如果發生此風險，最終評分可能偏差 ±5 分」
```

### 回應 4：「暫停，我要重新檢查需求」
```
Claude Code 應該：
✓ 保存本計劃（Markdown 格式）
✓ 告訴用戶計劃文件位置
✓ 等待用戶重新提交需求
✓ 用戶再次提交後，從步驟 4 重新開始

保存格式：
計劃_[場景]_[時間戳].md
例如：計劃_三維獵殺_AAAA_20260605_140530.md
```

## ⏱️ 這一步驟的耗時

| 情況 | 耗時 |
|------|------|
| 簡單場景（1-2 個維度） | 2-3 分鐘 |
| 標準場景（3-4 個維度） | 3-5 分鐘 |
| 複雜場景（5+ 個維度） | 5-8 分鐘 |
| 用戶需要詳細解釋 | +3-5 分鐘 |
| 用戶要求修改計劃 | +2-5 分鐘 |

**總耗時範圍**：3-15 分鐘（取決於複雜度和用戶確認速度）

## 💡 設計目的

### 為什麼需要步驟 4.5？

```
場景 1：無計劃直接執行
  用戶要求 → Claude 直接執行 → 用戶可能不滿意 → 怪 Claude

場景 2：先生成計劃再執行
  用戶要求 → Claude 生成計劃 → 用戶確認 → Claude 執行 → 用戶滿意

優勢：
✓ 用戶完全掌握執行過程
✓ 提前發現問題（成本、時間、風險）
✓ 提高決策自信度
✓ 減少執行中途改變主意
✓ 建立信任（透明的流程）
```

### 最佳實踐

#### ✅ 做這些
- 生成清晰、詳細、可驗證的計劃
- 用結構化表格展示成本、時間、風險
- 給用戶明確的確認選項
- 根據用戶反饋快速調整
- 保存計劃供複用

#### ❌ 不要做這些
- 生成模糊的計劃
- 隱藏成本或風險估算
- 強制執行（如果用戶沒有明確確認）
- 修改計劃後不再次確認
- 計劃和實際執行差異太大
